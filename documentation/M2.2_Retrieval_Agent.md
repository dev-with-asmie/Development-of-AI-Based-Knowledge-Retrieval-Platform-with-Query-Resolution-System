
# M2.2 – Retrieval Agent

## 1. Overview

The Retrieval Agent is responsible for retrieving relevant information from the knowledge base based on the user's query and its classification.

It builds upon the document ingestion, embedding generation, vector indexing, and hybrid retrieval functionality developed during Milestone 1.

The agent retrieves relevant document chunks, applies relevance filtering, ranks the retrieved information, and returns structured results with source metadata.

## 2. Objectives

- Retrieve relevant document chunks for user queries.
- Support factual, procedural, and comparative queries.
- Reuse the existing M1 hybrid retrieval pipeline.
- Apply relevance and semantic similarity thresholds.
- Return ranked results with source information.
- Handle ambiguous queries and unavailable information.
- Provide a retrieval confidence indicator.

## 3. Architecture

The retrieval process follows these steps:

1. Receive the user query and its classification from the Query Understanding Agent.
2. Validate the query and classification.
3. Check whether clarification is required.
4. Call the existing M1 retrieval service.
5. Retrieve additional candidate chunks for filtering.
6. Apply minimum relevance and semantic similarity thresholds.
7. Rank and select the top-K relevant results.
8. Calculate the aggregate retrieval confidence.
9. Return structured retrieval results.

## 4. Supported Query Types

| Query Type | Description |
|---|---|
| Factual | Retrieves information that answers specific questions. |
| Procedural | Retrieves instructions, steps, and documented procedures. |
| Comparative | Retrieves information relevant to comparisons. |
| Ambiguous | Returns a clarification-required status. |

Ambiguous queries are not passed to document retrieval.

## 5. Retrieval Method

The agent reuses the hybrid retrieval service implemented in M1.

The retrieval pipeline combines:

- Semantic similarity using sentence embeddings.
- Keyword-based matching.
- Relevance scoring.
- Structured field-aware retrieval for ticket records.

The existing hybrid retrieval service calculates a relevance score using:

Relevance Score = (0.70 × Keyword Score) + (0.30 × Semantic Similarity Score)

For structured ticket records, field-aware filtering is used instead of semantic similarity scoring.

## 6. Relevance Filtering

The Retrieval Agent applies the following default thresholds:

| Query Type | Minimum Semantic Similarity |
|---|---:|
| Factual | 0.20 |
| Procedural | 0.20 |
| Comparative | 0.15 |

The default minimum relevance score is 0.20.

Structured CSV results with no semantic similarity score are preserved because they are retrieved using field-aware filtering.

These thresholds are initial heuristic values selected during testing. They are not calibrated confidence probabilities.

## 7. Retrieved Metadata

Each retrieved result contains:

- Rank
- Source filename
- Chunk index
- Retrieved text
- Semantic similarity score
- Keyword score
- Relevance score
- Matched structured records, when applicable

Page-level and section-level metadata are not currently available in the existing ingestion pipeline.

## 8. Retrieval Confidence

The agent calculates retrieval confidence as the average relevance score of the returned results.

Retrieval Confidence = Sum of Result Relevance Scores / Number of Retrieved Results

This is an application-level retrieval indicator, not a statistically calibrated probability of answer correctness.

If no relevant results are found, retrieval confidence is set to 0.0.

## 9. Error and Edge Case Handling

The Retrieval Agent handles:

- Empty queries through input validation.
- Invalid classifications through validation.
- Unsupported query types through validation.
- Ambiguous queries through clarification-required responses.
- Low-relevance results through threshold filtering.
- Unavailable information through a no-relevant-results response.

## 11. Current Limitations

- Comparative retrieval may return only one relevant passage, which may not be sufficient to support a complete comparison.
- Retrieval confidence is a heuristic based on relevance scores.
- Page and section metadata are not yet included.
- Retrieval quality depends on the available indexed documents and the initial relevance thresholds.
- Response generation and final answer synthesis are handled in the next development stage.

## 12. Conclusion

The Retrieval Agent successfully integrates the existing M1 retrieval pipeline with the query classification output from M2.1.

It supports factual, procedural, and comparative retrieval, applies relevance filtering, preserves source information, and handles unavailable information.

The implementation establishes the retrieval component required for the Response Generation Agent in M2.3.
