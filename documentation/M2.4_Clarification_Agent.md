
# M2.4 – Clarification Agent

## 1. Objective

The Clarification Agent is responsible for handling ambiguous or incomplete user queries.

It works with the Query Understanding Agent to identify when additional information is required before retrieving relevant documents.

Its main objective is to improve query accuracy by requesting clarification instead of sending unclear questions directly to the Retrieval Agent.

## 2. Responsibilities

The agent performs the following tasks:

- Accepts the original user query.
- Uses the Query Understanding Agent's classification.
- Identifies the type of missing information.
- Generates an appropriate clarification question.
- Routes clear queries towards retrieval.
- Returns a structured response indicating whether clarification is required.

## 3. Integration with Query Understanding Agent

The Clarification Agent imports the existing `classify_query()` function from the Query Understanding Agent.

The Query Understanding Agent identifies whether a query is factual, procedural, comparative, or ambiguous.

If the query is ambiguous, the Clarification Agent determines what additional information is needed.

This separation keeps query classification and clarification generation as independent responsibilities.

## 4. Clarification Categories

The implementation supports four clarification categories:

| Category | Purpose |
|---|---|
| missing_context | Handles vague follow-up questions |
| missing_comparison_targets | Identifies unspecified comparison items |
| missing_subject | Handles questions without a clear subject |
| unclear_intent | Handles queries whose purpose is not understood |

## 5. Clarification Generation

The agent uses predefined clarification templates.

Examples:

**Vague follow-up:**

User: "What about it?"

Response: "Could you provide a little more context about what you are referring to?"

**Missing comparison targets:**

User: "Compare them."

Response: "Which two items, concepts, or approaches would you like me to compare?"

**Missing subject:**

User: "How does it work?"

Response: "Which system, process, or concept would you like me to explain?"

## 6. Input Structure

The agent accepts:

- A user query.
- An optional classification dictionary from the Query Understanding Agent.

If a classification is not provided, the agent automatically calls `classify_query()`.

## 7. Output Structure

When clarification is required:

```python
{
    "success": True,
    "status": "clarification_required",
    "original_query": "Compare them.",
    "clarification_question": "Which two items, concepts, or approaches would you like me to compare?",
    "clarification_type": "missing_comparison_targets",
    "requires_clarification": True
}
```

When clarification is not required:

```python
{
    "success": True,
    "status": "ready_for_retrieval",
    "original_query": "What is a computer network?",
    "clarification_question": None,
    "clarification_type": None,
    "requires_clarification": False
}
```

## 8. Validation and Error Handling

The agent validates:

- Non-empty user queries.
- Classification input type.
- Supported query categories.

It raises appropriate validation errors for empty queries, invalid classification types, and unsupported query categories.

## 10. Limitations

- Clarification questions are generated using predefined rules and templates.
- The agent does not maintain multi-turn conversation context independently.
- Complex ambiguous queries may require more advanced clarification logic.
- The agent has not yet been connected to the complete multi-agent orchestration workflow.

## 11. Conclusion

The Clarification Agent provides a structured mechanism for handling ambiguous user queries.

By working with the Query Understanding Agent, it helps ensure that incomplete questions receive clarification before document retrieval.
