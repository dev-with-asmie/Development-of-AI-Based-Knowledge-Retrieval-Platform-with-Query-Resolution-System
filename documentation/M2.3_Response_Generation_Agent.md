
# M2.3 – Response Generation Agent

## 1. Objective

The Response Generation Agent is responsible for generating clear, document-grounded answers using the relevant passages returned by the Retrieval Agent.

It uses a language model to formulate answers while ensuring that responses remain supported by the retrieved knowledge base.

The agent is designed to reduce unsupported answers and provide source references for transparency.

## 2. Responsibilities

The main responsibilities are:

- Accept the original user query and retrieval results.
- Construct a structured prompt using retrieved document passages.
- Generate answers using the Gemini API.
- Ensure responses are grounded in the supplied document context.
- Preserve source information for answer traceability.
- Handle clarification requests and cases where relevant information is unavailable.
- Validate source citations in generated answers.
- Handle generation errors and empty responses.

## 3. Input Structure

The agent accepts two primary inputs:

### User Query

The original question submitted by the user.

### Retrieval Result

A dictionary containing the retrieval status, retrieved passages, and retrieval confidence.

Example:

```python
{
    "status": "retrieved",
    "results": [
        {
            "source": "networking.pdf",
            "chunk_index": 0,
            "text": "A computer network connects multiple devices.",
            "relevance_score": 0.92
        }
    ],
    "retrieval_confidence": 0.92
}
```

The agent also supports an optional custom generator function for testing without making real API calls.

## 4. Prompt Construction

The agent constructs a structured prompt using:

- The user's original question.
- Retrieved document content.
- Source identifiers.
- Document filenames.
- Chunk indices.

Each retrieved passage receives a source identifier, such as `[Source 1]` or `[Source 2]`.

The prompt instructs the language model to:

1. Answer using only the supplied document context.
2. Avoid inventing unsupported facts.
3. Explain when the available context is insufficient.
4. Provide clear and direct answers.
5. Include source references for supporting information.
6. Use numbered steps for procedural questions when appropriate.

Retrieved content and user input are serialized as JSON data before being included in the prompt.

## 5. Gemini API Integration

The agent uses Google's Gemini Interactions API for response generation.

The implementation uses:

- Python Google GenAI SDK.
- Gemini model configured through the environment variable `GEMINI_MODEL`.
- API key loaded through `GEMINI_API_KEY`.
- A default model configured in the agent.

Sensitive credentials are stored in the `.env` file and are not included in source control.

The agent also supports an injectable generator function, allowing unit tests to run without external API access.

## 6. Prompt-Injection Protection

Retrieved document passages may contain instructions unrelated to the user's question.

To reduce prompt-injection risks, the agent:

- Treats retrieved document content as untrusted data.
- Treats user input as data rather than system instructions.
- Instructs the language model not to follow instructions embedded in uploaded documents.
- Restricts the model to using retrieved content as evidence.
- Instructs the model not to reveal hidden instructions or perform unrelated actions.

These measures provide prompt-level protection but do not guarantee complete prevention of prompt injection.

## 7. Citation Validation

The agent preserves source metadata for every usable retrieved passage.

Generated answers may reference sources using identifiers such as:

- `[Source 1]`
- `[Source 2]`

A citation-validation function checks whether every recognized source citation corresponds to a source supplied to the generator.

If an answer references a source that was not supplied, the agent rejects the response and returns a generation failure.

This helps prevent fabricated source references.

Citation validation checks source identifiers; it does not independently verify that every cited passage actually supports the associated claim.

## 8. Output Structure

For successful generation, the agent returns:

```python
{
    "success": True,
    "status": "generated",
    "query": "What is a computer network?",
    "answer": "A computer network connects devices. [Source 1]",
    "sources": [...],
    "retrieval_confidence": 0.92,
    "model": "custom_generator"
}
```

The output includes:

- Success status.
- Generation status.
- Original query.
- Generated answer.
- Source metadata.
- Retrieval confidence.
- Model identifier.

## 9. Error Handling

The agent handles the following situations:

| Situation | Behaviour |
|---|---|
| Empty user query | Raises a validation error |
| Invalid retrieval input | Raises a validation error |
| Clarification required | Returns a clarification message |
| No relevant results | Returns an appropriate no-information message |
| Empty retrieved content | Avoids unnecessary generation |
| Empty generated answer | Returns generation failure |
| Generator/API exception | Returns generation failure |
| Invalid source citation | Rejects the generated answer |

## 11. Limitations

- Real Gemini generation has not yet been fully validated because API requests have encountered timeouts.
- Prompt-injection protection is instruction-based and is not a guarantee against all attacks.
- Citation validation checks source identifiers, not factual support for each citation.
- Response quality depends on the relevance and completeness of retrieved passages.
- The agent has not yet been connected to the complete multi-agent orchestration workflow.

## 12. Conclusion
