
# M2.1 – Query Understanding Agent

## 1. Objective

The Query Understanding Agent is the first component of the multi-agent query resolution pipeline.

Its primary responsibility is to analyse incoming user queries, identify their intent, classify them into predefined categories, and determine the appropriate processing route.

The agent prepares structured query information for the subsequent Retrieval Agent and identifies ambiguous queries that require clarification.

## 2. Scope

The M2.1 implementation includes:

- Query intent classification.
- Identification of factual, procedural, comparative, and ambiguous queries.
- Rule-based classification logic.
- Classification confidence estimation.
- Routing information generation.
- Detection of queries requiring clarification.
- Testing using representative queries from two knowledge domains.

## 3. Query Classification Categories

The agent supports four query categories.

### 3.1 Factual Queries

Factual queries request specific information, facts, values, definitions, or details from the knowledge base.

Examples:
- What is the status of ticket T-503?
- List all critical priority tickets.
- Who is responsible for updating the policy?

Routing: Retrieval Agent.

### 3.2 Procedural Queries

Procedural queries request instructions, explanations of processes, workflows, or steps required to perform an activity.

Examples:
- How do I update a ticket status?
- How can I configure email notifications?
- Explain the process for submitting an expense claim.

Routing: Retrieval Agent.

### 3.3 Comparative Queries

Comparative queries request comparisons, similarities, differences, or relative evaluations between two or more items.

Examples:
- Compare critical and high priority tickets.
- What is the difference between open and resolved tickets?
- Compare the password reset procedure with account recovery.

Routing: Retrieval Agent.

### 3.4 Ambiguous Queries

Ambiguous queries lack sufficient information or context to determine the user's exact intent.

Examples:
- What about it?
- Which one?
- Tell me more.
- Can you help?

Routing: Clarification handling.

Actual clarification conversations are planned for a subsequent milestone.

## 4. Technical Approach

The initial Query Understanding Agent uses a rule-based classification approach implemented in Python.

It analyses the normalized user query and checks for predefined linguistic patterns.

The classification process follows these steps:

1. Receive the user's query.
2. Validate that the query is not empty.
3. Normalize the query by converting it to lowercase and removing trailing punctuation.
4. Detect vague follow-up questions and insufficient context.
5. Match the query against comparative, procedural, and factual patterns.
6. Assign a query category.
7. Estimate classification confidence using predefined heuristic values.
8. Determine the routing destination.
9. Return a structured classification result.

Comparative patterns receive priority over procedural and factual patterns to avoid incorrectly classifying explicit comparison requests.

## 5. Classification Confidence

The agent provides a heuristic confidence estimate based on the strength of the detected classification rules.

The current implementation uses the following values:

| Classification condition | Confidence |
|---|---:|
| Explicit comparative pattern | 0.95 |
| Explicit procedural pattern | 0.90 |
| Explicit factual pattern | 0.90 |
| Recognized vague follow-up | 0.95 |
| Insufficient query context | 0.85 |
| No clear intent pattern | 0.55 |

These values are rule-based estimates and are not calibrated probabilities.

## 6. Structured Output Format

The agent returns a structured Python dictionary containing:

- original_query
- normalized_query
- query_type
- classification_confidence
- routing
- requires_clarification
- matched_rules

Example output:

```json
{
  "original_query": "What is the status of ticket T-503?",
  "normalized_query": "what is the status of ticket t-503",
  "query_type": "factual",
  "classification_confidence": 0.9,
  "routing": "retrieval",
  "requires_clarification": false,
  "matched_rules": [
    "\\bwhat\\b",
    "\\bstatus\\b"
  ]
}
```

## 7. Routing Strategy

The agent determines the next processing destination based on the identified query category.

| Query category | Routing destination |
|---|---|
| Factual | Retrieval |
| Procedural | Retrieval |
| Comparative | Retrieval |
| Ambiguous | Clarification |

Queries classified as factual, procedural, or comparative are marked for retrieval.

Ambiguous queries are marked with `requires_clarification = true` and routed to clarification handling.

The actual orchestration and clarification interaction will be implemented in subsequent development tasks.

## 8. Testing and Validation

A test dataset containing 16 representative queries was created.

The dataset covers two knowledge domains:

**Domain 1: Ticket Management**
- Ticket status and priority queries.
- Ticket update and resolution procedures.
- Comparisons between ticket priorities and statuses.
- Ambiguous follow-up questions.

**Domain 2: General Documents and Procedures**
- Policy-related factual questions.
- Configuration and submission procedures.
- Comparisons between policies and procedures.
- Ambiguous questions.

Each test case includes an expected classification and is compared against the agent's actual output.

### 8.1 Test Results

| Query category | Test cases | Correct |
|---|---:|---:|
| Factual | 4 | 4 |
| Procedural | 4 | 4 |
| Comparative | 4 | 4 |
| Ambiguous | 4 | 4 |
| **Total** | **16** | **16** |

### 8.2 Classification Accuracy

Classification accuracy is calculated using:

Accuracy = (Correct Classifications / Total Test Cases) × 100

Accuracy = (16 / 16) × 100

**Observed Classification Accuracy: 100%**

All 16 representative test cases passed successfully.

This result applies only to the current test dataset and does not establish general performance on unseen queries.

## 10. Limitations and Future Improvements

The current implementation uses predefined linguistic rules rather than a trained machine learning model or an LLM-based intent classifier.

Potential improvements include:

- Supporting more complex and context-dependent queries.
- Improving classification of queries containing multiple intents.
- Incorporating conversation history for follow-up questions.
- Calibrating confidence using a larger labelled dataset.
- Expanding test coverage across additional knowledge domains.
- Integrating clarification handling and multi-agent orchestration.

## 11. Conclusion

The Query Understanding Agent establishes the first stage of the multi-agent query resolution architecture.

It successfully identifies factual, procedural, comparative, and ambiguous queries and generates structured classification and routing information.

Testing on 16 representative queries across two knowledge domains resulted in 100% observed classification accuracy.

The component provides the foundation for the Retrieval Agent developed in M2.2.
